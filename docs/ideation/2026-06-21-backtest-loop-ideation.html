KSS 回测闭环补强

用持续回测加强复盘与预测准确性 · 服务「跟踪自选」+「发现潜力股」
ce-ideate · 2026-06-21 · repo-grounded · 7 survivors / 19 raw · 5 axes

立项判断

KSS 的回测地基已经很硬：walk-forward 引擎、purge gap、Deflated Sharpe、8 层 bias 逐层剥离、log_mv 反向是唯一通过 DSR 门槛的实盘策略（Sharpe 1.74，DSR 0.754），每日纸交易 + 每周 validate_predictions 校准。

真正的缺口不在「能不能回测」，而在 回测/校验的结论没有形成闭环——它们是手工一次性分析，不会自动回流去改进模型、阈值与发现逻辑。下面 7 条都围绕「把已有的诊断能力接成一个会自我纠偏的环」。

Grounding 要点

已有的强项
  • walk-forward + purge + DSR + bootstrap CI（significance.py）
  • 对抗偏差测试 18 pass / 3 xfail（test_adversarial.py）
  • 每周预测校验：Brier / 覆盖率 / 方向命中（validate_predictions.py）
  • 每日纸交易 T+N 跟踪 + Sharpe 衰减告警
已证实的痛点
  • 无 IC/ICIR/Rank-IC 的跨时间滑轨，看不到因子衰减
  • 回测结论不自动回流改模型/阈值（8 轮全手工）
  • daily_review 次日预测 ≈ 随机（Brier 0.828、方向 43% 系统性反向、80% 区间只覆盖 53%）
  • Feature-level look-ahead gap 未堵（派生未来特征会泄漏，seed 全部 Sharpe≥5）
  • 4 条发现管道（log_mv / 北证扫描 / 板块热度 / 紫苏叶）互不合并，多处阈值硬编码无回测支撑
  • Kronos K线基模型孤儿化（.pyc vendored、predictions.sqlite 悬空、零 .py 集成）

主题轴（surface）

  1. 回测引擎与策略评估 — 如何更可信地验证、防偏差
  2. 预测/选股模型 — log_mv / kronos / 因子如何选股、如何监控衰减
  3. 复盘与归因反馈 — 复盘结论如何结构化喂回
  4. 自选跟踪 — 推荐/自选的 T+N 跟踪与失败归因
  5. 潜力股发现 — 多管道筛选、合并、有效性验证

排名建议（7 条）

1

因子健康度闭环：滚动 IC/ICIR + 衰减告警 + 崩盘登记库

模型/回测信心 高复杂度 M

把每条因子/信号的 Rank-IC、ICIR 按滚动窗口逐期算并落库，配 1d/5d/20d 的 IC 衰减半衰期。当 60 日滚动 ICIR 跌破基线阈值 → 自动告警、标记待复核、可触发剔除；每次回测把「哪个因子在哪个窗口崩、崩成什么样」写进因子崩盘登记库，加速以后新因子评估。

basis
direct: 多个 scout 指出「无 IC/ICIR 滑轨」「无自动反馈环」「无系统记录哪些因子在哪窗口崩盘」；external: alphalens-reloaded（IC/IC-decay/turnover）、AlphaAgent 用 ICIR 退化做换因子门。
为什么重要

这是「用回测加强预测」最直接的形态——把一次性的 8 轮人工剥离，变成天天在跑的因子体检。一旦建好，后面所有新因子/新管道都免费接入同一套体检，是复利层。

下行风险

A 股横截面单位高相关→ t 检验有效 n 是去重日期数（etf_flow 教训）；阈值本身要先 walk-forward 标定，别又造一个硬编码门。

2

预测生命周期账本：一条预测从发出→实盘→结算→归因全链路

复盘/跟踪信心 高复杂度 M

现在预测在 paper_trade JSON、validate_predictions 报告、复盘 markdown 里各存一段，对不上。建一个单一事件账本：每条预测带稳定 id，记录入选理由（因子值/管道/regime）、T+N 实际收益、对错，并强制补一段结构化归因（为什么对/错：是因子失效、regime 切换、还是执行摩擦）。下游复盘/回测/IC 都从这张账本取数。

basis
direct: review scout：「validation 结果从不回流」「失败原因不持久化」；watchlist scout：「缺失败归因」。reasoned: 没有共享账本，复盘/校验/回测就会各算各的、永远对不齐。
为什么重要

归因是闭环的「学习」环节——没有结构化的「为什么错」，模型永远改不动。账本也是第 1、3 条的共同数据底座。

下行风险

归因若交给 LLM 自由写会产幻觉数字（龙虎榜事故先例）——真值代码渲染、LLM 只给定性标签；外部快照数据严禁回流账本做回测（PIT 红线）。

3

修复 daily_review 次日预测（校准优先，而非加复杂度）

复盘信心 高复杂度 S

次日情形分布实测 ≈ 随机且已定停用判据。按已知四个根因修：① 区间以无条件波动分位为底加宽；② 加 regime 开关（均值回归先验在动量 regime 下关掉）；③ 删常量「5–10 日仍看涨」这种无区分度输出；④ 止损改为仓位语义、与中期观点解耦。用 Brier 的校准 vs 分辨分解定位（很可能分辨尚可、校准崩）。

basis
direct: daily_review_prediction_validation.md：Brier 0.828、方向 43% 反向、80% 覆盖 53%、四根因已列、停用判据已定。external: 超预测/气象用 Brier 拆校准+分辨、isotonic 后验校准。
为什么重要

这是一个正在触发停用线的已上线功能——要么修复要么撤掉。根因已诊断清楚，是 ROI 最高的「修死功能」。

下行风险

修不好就按判据果断撤段，别让随机预测占版面误导。

4

堵 feature-level look-ahead + 对抗测试进 CI（信任地基）

回测信心 高复杂度 S

当前 purge_gap 只防 label 泄漏；若把含未来信息的派生特征塞进 feature_cols，test 阶段照样作弊（seed 0/1/2 全部 Sharpe≥5）。加 walk-forward 入口校验：任一特征与未来收益 IC>0.95 直接拒绝；并把 test_adversarial.py 设为 CI 必跑。

basis
direct: known_bias_gaps.md Gap #1 仍 open、test_adversarial.py 未入 CI。
为什么重要

前三条都依赖回测可信。这道门没堵，任何新模型都可能在 test 上偷看未来而不自知——是其余补强的前提。低成本高杠杆。

下行风险

IC 阈值过严会误杀强短周期特征；阈值给逃生口 + 人工复核名单。

5

统一发现管道合并层 + 管道级 alpha 评分

发现信心 中复杂度 M

log_mv / 北证扫描 / 板块热度 / 紫苏叶四条管道各打各的分、互不合并、去重过简。建合并层：跨管道共识加权（多管道同时命中→升权）+ 统一去重；并给每条管道单独算回测 alpha/IC，按有效性排管道权重，替掉硬编码阈值（北证六维权重、轮动 rank_jump=50 等）。

basis
direct: discovery scout：4 管道独立无合并、阈值硬编码无回测支撑、OOS 窗口过短（min_n=5）。reasoned: 「哪个管道更准」只能用回测 IC 回答，倒逼出管道级 alpha。
为什么重要

直接服务「发现潜力股」——把四条各自为政的管道变成一个按实证有效性自动配比的发现器。

下行风险

紫苏叶手工标注覆盖不足、样本小；管道相关性高时共识加权会放大共同偏差，需先测管道间相关。

6

CPCV 组合净化交叉验证：从「一个幸运窗口」到 OOS 分布

回测信心 中复杂度 L

当前 walk-forward 给的是点估计，而 KSS 的核心风险恰恰是「Sharpe 在不同窗口塌掉」。引入 Combinatorial Purged CV（10 折取 4 测 = 210 条 OOS 路径），得到 Sharpe/IC 的分布而非单值，直接喂进已有的 DSR / PBO 门槛。

basis
external: López de Prado CPCV、skfolio CombinatorialPurgedCV（purge/embargo 参数）、Numerai 实测 210 条 OOS 路径；direct: lookahead 教训里 Sharpe 跨窗口从 1.93 塌到 -0.53 的衰减史。
为什么重要

把「这条策略到底稳不稳」从一次抽样升级成分布判断，是回测可信度的天花板提升。

下行风险

算力成本上升（210 路径 vs 1）；对单用户本地工具要控规模、可缓存折叠。复杂度最高，建议排在 1–4 之后。

7

Kronos 从孤儿转「影子裁判」：regime/不确定性弃权门，而非选股器

模型信心 中复杂度 L

Kronos 直接选股没通过（基模型 PIT 无法证清白，TimesFM 先例已否决「外部模型直接选股」）。换个用法：让它当影子裁判——输出每日不确定性/regime 信号，给 log_mv 的选股加一道「弃权门」（不确定性高→当日降仓或弃权），而不参与选谁。先影子运行、用账本对比，不进实盘直到证明有边际。

basis
direct: prediction scout：Kronos vendored 但零集成、predictions.sqlite 悬空；external:「When Alpha Breaks」regime-trust gate G(t)（弃权而非预测）。
为什么重要

盘活一个已 vendored 的资产，且绕开它最致命的弱点（PIT 不可证）——只用它做门控不做选股，举证负担小得多。

下行风险

仍需证 PIT 清白（基模型 cutoff 未披露的老问题）；先纯影子、用第 2 条账本量化是否真有边际，无边际就果断弃。复杂度高，列为 potential。
